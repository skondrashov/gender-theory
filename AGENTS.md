# gender-theory

You are the maintainer of **gender-theory**, a browser-based generative audiovisual piece by the owner: music plays, and a grid of lines on a black canvas moves to it — driven by where the track is in its bar and by the live frequency spectrum. It is becoming a non-linear way through an album: the album is a graph of **scenes** (looped sections of tracks), each with **hotspots** the player taps or draws on; some grant **unlocks** that change how every scene is seen (a cell is a dot, a line out of it and a ring round it, described by twelve rows, one per unlock: brightness (glow), lines, length, angle, bend, rings, size, fill, morph, flatness, rotation, color), some lead on. Scenes are grouped under **paired words** (for/against, being/useless, terra/firmament, …): binaries and false binaries. That conceit is the title. It is an art project, not a product.

Load this file as your system prompt (`claude --system-prompt "$(cat AGENTS.md)"`) and work directly — there are no subagents. You are a solo creative-coding collaborator. The owner designs; you own the technical side. Preserve the owner's aesthetic decisions; ask before changing anything that reads as taste (palette, motion, word lists, which track goes where). Read `SPEC.md` first — the owner's design in layers (mechanics, songs, the album graph), decided vs. open — then `memory/notes.md`: build facts, track bar counts, and the decisions made so far.

## How it works

Two Rust crates, one repo:

```
src/main.rs        actix-web dev server on 127.0.0.1:8080
                     /     → static/   (index.html + mp3s)
                     /app  → app/pkg   (the built wasm + JS glue)
app/               the nannou sketch, crate-type cdylib, lib name `gender`
  src/lib.rs         main_web(): nannou app builder for the web; URL flags
  src/model.rs       Model: scene graph state, input, trail, menu; update()/view()
  src/audio.rs       Web Audio: decode tracks once, loop sections sample-accurately,
                     schedule changes on the audio clock
  src/progress.rs    scene + unlocks in localStorage
  src/names.rs       the exits' names: random_words shuffled once a game (seed in localStorage)
  src/words.rs       the word lists
  src/scenes/mod.rs  the data model: Track, Scene, Hotspot, Gesture, Action, Unlock,
                     Area, Regions, Subdivision; mark()/paint() drawing helpers
  src/scenes/data.rs the album as data: album.json → Scenes; bands, params, sidechains
  src/scenes/fields.rs position as a source: the field library (ripple, spiral, orbit, …)
  src/scenes/*.rs    hand-written scenes (the demo graph, the old scenes)
static/index.html  grey page; fetches album.json, `await init(); main_web(album)`
static/album.json  the album (see Album, below)
static/editor.*    the editor (see Editor, below)
static/music/      the album's mp3s (sine, sasha-grips, pisser, for-against)
static/{bu,fa,tf}/ old excerpts for the demo graph and old/* scenes. tf/ = byte copies of fa/.
tools/phases.py    tempo + phase detection for cutting a track into scenes
memory/notes.md    cross-session notes (build facts, bar counts, decisions)
```

**Data model** (`scenes/mod.rs`): a `Track` is one mp3 with a `bpm`; bar 0 is t = 0 (Ableton bounces start on a bar line). A `Scene` is `{ id, track, bars: Range, render, hotspots }` — a looped bar range plus a render closure called once per cell of the 11×11 grid per frame with `(draw, model, i, j, time, modifiers)`, `modifiers = [whole, half, quarter, eighth, sixteenth, bass, mid, treble]`. A `Hotspot` is `{ cells: Area, needs: Unlocks, on: Gesture, then: Action, tag }`: invisible and inert until the player has `needs`; the scene draws the hint itself (`model.hint_visible(tag)`). Gestures: `Tap`, `Drag { to }`, `Outline` (draw the perimeter of `cells` in one stroke; locks in while on it). Actions: `Go(id)` (next bar), `GoVia(id, bars)` (a transition: play those bars of the *current* track while the current scene intensifies per `model.transition()`, then switch), `Unlock(u)` (immediate; never moves you — a spent unlock hotspot disappears so a second hotspot on the same cells can be the door), `All(&[..])`. Unlocks are global; `model.reveal(u)` eases 0→1 over 2.5 s after unlocking and `mark()`/`paint()` use it (line grows from the point, stretches, winds up to speed, color fades in). `Regions` + `model.ticks(Subdivision)` let an effect walk across the screen one region per tick.

**Album** (`scenes/data.rs`, `static/album.json`): everything is measured in **bars of a track**. A track has `scenes` — **stretches**: `bars` plays once from its start, then from `loop` to its end repeats until the player leaves (a door `go`es to another scene at the next bar, as before). A scene has `stages` (its visual states, by name, in order: the player starts in the first and moves by hotspots whose action is `stage`, at the next bar, the music untouched — so a stretch lasts as long as it takes to get through a few stages, then loops waiting for the door out), `layers` (a `region` of the grid + a `kind` of mechanic + its `params`, in draw order, optionally one `stage`, optionally `bars` of its own — the whole scene by default) and `hotspots` (a `region` like a layer's — the outline gesture and hints use the rectangle round it — `needs`, `on`, `then`, optionally a `stage`; its `name` is what a `text` layer with `hotspot: <its id>` says — **named exits**: a name of `name 1` … `name 4` is one of the room's random words, anything else is shown as written; rooms are the album's scenes in order, room r's exit k is word r × 4 + k of one shuffle of `random_words` per game, whose seed lives in localStorage beside the progress, so names hold through saves, transitions and reloads until the editor's **reset names** or the game's `?reset`). A scene draws its layers that are in the current stage and live at the bar the music is on (`model.bar()`). The editor keeps a scene's contents inside its bars (they move with it), can move a layer or hotspot to another scene, and the top bar's stage picker views any stage of the playing scene — the lists show that stage's layers and hotspots (plus the stageless ones), and new ones go into it. Regions: a `rect`, a `map` (11 rows of 11 chars, `#` in), every nth `rows`/`cols`, one `checker` color, the `perimeter` — all that are given must hold. Kinds: nearly every layer is `cells` — every cell in the region is a dot with a line out of it and a ring round it, described by twelve **rows**, one per unlock (`ROWS` in data.rs, in order: brightness; lines, length, angle, bend; rings, radius, fill, morph, flatness, rotation; color). A cells layer carries only the rows it changes and, for each, an `op` — `set`, `add` or `multiply` — on what the layers before it left (nothing: a dark dot, brightness 0); a new layer is one row, brightness 1. A row is a param (below); the angle rows can also `spin` (degrees per time unit; `alternate`: every other cell the other way). An unlock is one of two things (`RowSpec::gate`): a **row** — lines, length, bend, rings, size, fill, morph, flatness, rotation, color: the row rests at a value until it (lines 0, length 1, rings 0, radius 0.4, the rest 0) and eases to the layers' value as it comes in — or a row's **sidechain option**: glow is brightness's and angle is angle's — the row is free from the start (dots at any brightness, lines pointing anywhere) and the unlock is its motion: sidechains and masks on the music, and spin. The line is length × lines, so lines 0 is the dot; the ring is radius × rings. The other kinds are their own thing and rows don't reach them: `snake` (one line through the region's cells in serpentine order that retreats leaving dots, or arrives from them — a snake of its own through each separate piece of the region: every other column, each blob of a map; `tail` gives the last dot a segment too), `bars` (every dot owns a segment: columns grow dot to dot, even ones up from the bottom, odd ones down from the top; every segment then pivots a quarter turn on its own dot so the columns tile into rows; the rows retreat in reverse; then the same three backwards — the rows grow again from the dots they went into, the segments turn back, the columns retreat — six parts of a bar each on the track's bars — written as an algorithm at the owner's request), `text` (words in the owner's **lattice font** — `tools/font.json`, drawn connect-the-dots on a 9 × 13 point grid inside one cell, `tools/font.py` → `scenes/font.rs`: a letter per box between four dots, ten a line on the eleven dots, wrapping in the region's rectangle; `align`, `lead`, `width`/`height` of the box the letters take, `center`, `reveal` 0..1 letter by letter, brightness, color; `hotspot`: say that hotspot's name instead, while it shows — the exit's name placed wherever the layer is), `hole` (in its region nothing the layers before it drew shows — lines and rings go, scenery too, the dots stay unless `dots` is off; tied to a `hotspot` it is that hotspot's cells while the hotspot shows: lines passing over a door vanish there), `orbits` (satellites) and `walk` (a modifier: a grid of regions lit one per tick, adding to the brightness and length of the cells under it). A row also has **masks** — sources shaped like sidechains that say how much of the row's change lands (1 all of it, 0 none, × `depth`): on distance / bearing / around a shape; on `hotspot:<id>` (1 while that hotspot shows) a hint; on `unlock:<name>` (its reveal) a row that waits for an unlock, or inverted fades out with it; on the music, motion. A mask is `×` (multiplied with the others: distance × pulse lands only where both say) or `+` (`add: true`: its share, depth × level, is added to what the × masks let through — distance + pulse lands where either says, and a + pulse on its own lights only on the pulse: glow on cells that are dark by default). There is no other "showing when" — only `stage`, `bars` and `muted` scope a layer. Any moving number is a **param**: `{base, chains: [{source, depth, threshold, width, curve, invert, on}]}` — the source's level goes through a smooth step from `threshold` over `width`, a power `curve`, optional inversion, and `depth` × that is added to the base. Sources: the album's **bands** (`{id, name, lo, hi, attack, release, gain, floor}` Hz ranges followed by a one-pole envelope in `Model::follow_bands`, from a 2048-point FFT — each gives its level as `id`, and the **pitch** of the loudest thing in its range as `id.pitch` (lo..hi, log scale, held while under `floor`) and `id.chroma` (its note, C = 0 .. B)) and the built-ins span (0..1 across the layer's own bars) / beat / bar / pulse / noise / **distance** (from the centre dot, 0..1 at a corner) / **bearing** (direction from it, 0 up, clockwise to 1) / **around** (the way round the layer's rectangle at the cell: 0 top, 0.75 right, 0.5 bottom, 0.25 left; × 360 on angle runs lines round it) / transition / bass / mid / treble. Phase ramps for animating things: `bar.phase` (0 at the downbeat to 1 at the next), `beat.phase`, `clock` (0..1 every time unit, music or not). **Position** is a source too: a chain or mask with `source: "position"` carries a `field` — `{fn, params}` from the library in `scenes/fields.rs` (`FIELDS`, ~40 of them in families: radial — distance, lamp, disc, ring, ripple, tunnel, shockwave; angular — bearing, petals, beam, sweep, mirror, kaleido, spokes; spiral — spiral, vortex, rose, star, polygon, dartboard, web; linear — gradient, curtain, stripes, waves, scanline, lattice, checker, plus, saddle; pairs — interference, dipole, nearest; bodies — orbit, comet, pendulum, lissajous, rain; scatter — noise (a seeded pattern: sidechain the seed for a new pattern on each kick, or `every` n beats), twinkle, reading, flow). A field is a function of where the cell is relative to a centre (`x`, `y`), facing `turn`, with a `phase` to run (sidechain it from a phase ramp) and, for radial ones, a `shape` (−1 diamond, 0 round, 1 square); **every parameter is a param of its own**, so a ripple's period can follow the bass and a beam can spin with the bar. A chain or mask on noise, distance, bearing, around, position, a hotspot or an unlock is fixed — a pattern or a state of the game — and always acts (a field's parameters pass the row's gate on to their own sidechains, so a pattern's motion still waits for the unlock); the rest are motion and come in with the row's unlock (`Param::value_gated`, `Row::amount`). The one place to add a field: a `FieldSpec` in `FIELDS` and an arm in `Field::eval`. A chain's `delay` makes a phase source (beat, bar, pulse, span, transition) arrive later by delay × distance — a ripple from the centre. The file also carries `presets`: layers kept as a library (`{id, name, layer}`), editor-only. Hand-written Rust scenes (`for_against.rs`) still work alongside, with the same `Scene` struct.

**Editor** (`/editor.html`, dev server running): the real renderer in the page (`?editor=<px>` makes the app a fixed square canvas that saves nothing and takes commands — `editor(json)`, `state()`, `spectrum()`, `catalogue()` exported from the wasm), an 11×11 grid to paint maps (what a new layer or hotspot starts as, empty; **clear** empties it again) or drag rects, lists of the track's scenes/hotspots/layers and the presets (a layer's "save as preset" keeps a copy; clicking a preset drops one into the current scene), an inspector generated from `catalogue()` (a layer: stage, bars, then its rows, each with an op, a base, its sidechains, its masks, the unlock that governs it, a live **readout** of what the row is worth at the **probe cell** — hover the region grid to move it; the engine reports `probe` in `state()` — and a picker for the rows it doesn't have yet; a `group` name — editor-only, a label on layers that make one thing together: the layer list folds a run of them under a header, and selecting the header edits them as one: stage, mute, move to a scene, duplicate, delete, + layer into it; a sidechain's source list ends with the position fields, grouped by family, and a field's parameters unfold beneath it), a sources panel (live log-scale spectrum, bands as draggable ranges with meters, built-in meters) and, in the bottom panel, a **timeline** in bars (waveform; click to play from there; drag blocks to move/resize) or the **graph** (a tab: every scene of every track as a node — its stages inside, with ◆ unlock and → stage hotspots as marks; an arrow per hotspot action that leads somewhere, labelled with its gesture, `needs`, via bars and stage; START on the first scene, the playing one lit, dashed when no door reaches it from the start, red ghosts for doors to nowhere — a hand-written scene is a grey ghost, `catalogue().elsewhere` — and a count of both in the tab strip. Click a node to edit that scene, ▶ to play it, drag to arrange — positions live on the scene as `graph: {x, y}`, the engine ignores them, a scene without one sits in its track's column — drag from a node's ○ onto another to make a door (a tap hotspot with an empty region to paint), drag an arrowhead to retarget, click an arrow to edit its hotspot, "× remove this door" on the selected one takes the action off it). Every edit is pushed live and **autosaved** 1.5 s after the last one (toggle in the top bar, remembered per browser; **save**/ctrl+s saves now; undo/redo). A save PUTs `static/album.json` through the dev server with a fingerprint of the file the tab loaded; the server answers 409 if the disk has moved on (another tab saved, a git checkout, a migration) and the tab stops autosaving — reload to take the disk's version, or press save to overwrite it. The deployed site has no server, so save downloads the file instead. `?editor` is also handy for driving the game page from scripts.

**Drawing** (`DOT` = 3 px dots, `WEIGHT` = 3 px round-capped lines, so a line covers its dot exactly; a line of length 0 is the dot): scenes draw through `mark()` (a line per cell) and `ring()`; these *record* a `Mark` rather than drawing, and `view()` draws the cell's marks afterwards. That is what makes **morphs** possible: for the last `MORPH` (1.5) seconds before a scene change lands — or whatever is left of them if it was asked for later — `view()` also renders the incoming scene's landing frame (top of its bar, `model.preview` set so hints/ticks are its own) and draws each cell `blend()`ed between the two: lines turn the short way round and stretch, rings resize, colors cross, unpaired marks grow in or shrink away. Anything a scene draws directly on `draw` (the `old/*` scenes) just snaps. The `time` a render gets is `app.time × 0.6` (frame-rate independent; 0.6 keeps the old speed).

**Audio**: tracks are fetched and decoded into `AudioBuffer`s (current scene's track plus everything reachable from visible hotspots). A section plays one pass at a time, each pass its own buffer source behind its own gain, scheduled 1.5 s ahead from `advance()`: fade in over the 20 ms before its bar line, hold, ring out 30 ms under the next pass; a scene change fades the new section in the same way and the old out over 80 ms from the bar line (`FADE_IN`/`LOOP_TAIL`/`CUT_TAIL` in `audio.rs`). Nothing is cut hard. Changes are scheduled on the audio clock so they land on the bar. A 2048-point `AnalyserNode` feeds the bands (`spectrum()`) and, folded to 16 bins, the old `bass/mid/treble`. Bar phase and the bar itself (`Audio::bar()`) come from the audio clock; the editor can start a scene mid-loop (`play_from`).

**Interaction**: first click starts the audio context. Tap = press+release in a hotspot; drags and outlines draw a white trail snapped to the dot lattice along grid lines, fading in 1.5 s. From a trigger until the new scene lands, input is blocked and the scene morphs into the next over the final stretch (no border: the morph telegraphs it). **M** opens the scene menu (whole graph; click to jump — lands a morph away; click an unlock to toggle). Progress is saved in localStorage.

**URL flags**: `?debug` overlay · `?scene=<id>` · `?unlock=glow+lines+angle` (any of the twelve, `Unlock::ALL`) · `?reset` (progress and the exits' names) · `?msaa=N`.

## Running

```sh
cargo run            # serves the COMMITTED build in app/pkg — works with no wasm toolchain
./run.sh             # rebuilds the wasm (cd app && wasm-pack build --target web), then cargo run
```

Open `http://localhost:8080`, click once; `http://localhost:8080/editor.html` is the editor (it needs this server to save). `run.sh` is a bash script; use Git Bash on this Windows machine. The build works with the current toolchain (see `memory/notes.md` for the exact pins and why). `wasm-pack build` writes straight into `app/pkg`, which is committed and is what `cargo run` serves and what gets deployed — so check a build in a browser before committing it, and `git checkout app/pkg` if it's bad. (wasm-pack also drops a `.gitignore` of `*` in there; it's untracked and harmless — ignore rules don't touch tracked files.)

## Known rough edges

1. The canvas is the browser viewport at load and doesn't follow a resize; the grid takes the shorter side (`Model::scaling` = min(w, h) ÷ 11, recomputed every frame), the rest is black.
2. The old scenes (`old/*`, the demo graph) were written for a 20 × 20 grid of 40 px cells and look wrong on 11 × 11.
3. `Cargo.toml` in both crates still carries the template's name/description/author placeholders; root `pkg/` is the template's stale webpack build — neither is used.

## Hard constraints

1. **The mp3s are the owner's music.** Don't replace, trim, re-encode, or "fix" them; don't add tracks without being asked. The one allowed edit is `tools/gapless.py`'s header frame (audio frames untouched). If a scene needs audio that doesn't exist, ask.
2. **Taste belongs to the owner.** Visual parameters, the word pairs, the scene order, the grey page, `COLOR` — all deliberate until told otherwise. Propose; don't quietly refactor the look.
3. **Deploys go through `~/projects/ops`** (static-site deploy of `static/` + `app/pkg`; the actix server is dev-only and binds `127.0.0.1` — keep it that way). Queue, don't push to the VM yourself.
4. Don't commit `target/` (either crate). `app/pkg` **is** committed on purpose.
